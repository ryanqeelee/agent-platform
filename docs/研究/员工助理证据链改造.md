# 员工助理证据链改造

基线：2026-09-11，origin/main 206aafb49d8f978bbc1a6345bbf9f49d686fe65d。
目标：该查时检索，有依据时深入分析，依据不足时如实表达；不增加固定规划/审查轮次。

## 架构决策

所有改动属于 WeKnora 员工助理；复用现有 KnowledgeQA 管线、AgentEngine、来源注册表与数据/执行工具。经营分析、权限、数据库 schema、公共 API、知识库内容不变。

1. 快速查询已有的问题理解调用同时输出检索需要与缺失条件；二者独立，允许查资料与澄清并存。保留通用 Agent 的原有意图语义；员工助理不再因为 follow_up 或 needs_user_input 单独关闭取证。无效输出沿用原问题与可检索默认行为，不猜业务对象。
2. 快速/深入共用平台重排模型选择规则，保持各自检索预算。快速在确实需要检索且取得候选之后才解析重排模型；问候、改写、空来源、零候选不依赖重排配置。深入沿用原有工具初始化时机。不得修改全局配置以修复单条调用链。
3. 回答上下文携带本轮真实范围和执行结果：未查询、无来源、查询无匹配、候选、失败/部分失败。候选不等于支持答案。用现有管线状态承接，不另建证据存储或第二执行引擎；现有失败处理保留可用结果，不能把失败报告成无资料。
4. 将足够回答的判断放在实际证据之后，在现有生成/Agent 决策中按问题部分判断直接支持、推导、未决和冲突；先答支持部分，再说明必要缺口。合并并精简现有提示原则，禁止业务关键词补丁、文件名/版本臆测或固定回答模板。每次追加工具调用应填补一个明确缺口，证据够就停止。
5. 传递既有 user-authored CustomMetadata，不能把内部 ingestion Metadata 当文档效力。保留原文、问答关系、记录位置与截断信息；表格记录不完整时复用完整文档/表格读取工具，不按 A/B 列位置猜业务含义。计算使用现有工具执行规则，核验输入与输出；检索到规则不代表计算已完成。
6. 历史是上下文，不是事实权威。员工快速管线停止在重排后按文字相似度重新注入旧轮知识引用，避免让已淘汰或适用条件已改变的证据重新进入本轮结果；保留聊天历史上下文及来源定位能力。当前条件变化或历史结论缺乏支持时重新取证、纠错；上下文压缩保留条件和未决状态，不新增跨轮证据缓存。

## 状态与路径

| 状态 | 快速 | 深入 |
| --- | --- | --- |
| 普通改写/问候，无新证据需要 | 直接生成 | 直接生成 |
| 有取证需要且能形成检索问题，同时缺现场条件 | 仍检索，按结果回答/澄清 | 自主取证，必要时澄清 |
| 无来源 | 明确本轮无检索来源；附件可支持自己的部分 | 使用真实工具/附件清单，不探索隐藏内部资料 |
| 有来源但无匹配 | 报告本次无匹配，不推断文档不存在 | 有新线索才继续，否则交代缺口 |
| 仅部分支持/资料冲突 | 支持部分可答，未决不猜 | 补适用条件，无法消解就保留差异 |
| 已取得规则，尚未计算 | 不声称经过工具核验 | 用现有计算能力执行并核对结果 |
| 检索或重排失败 | 保留现有错误/降级边界及可用资料 | 依据实际失败结果决策 |
| 多轮补充/纠正条件 | 不因 follow_up 自动跳过新依据 | 更新结论，必要时重新取证 |
| 非员工助理入口 | 原意图/模式行为保持 | 原工具/配置行为保持 |

## 借鉴来源及适用范围

- [Google Sufficient Context](https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/)：区分相关性与能否支持完整回答；不把模型自评分当确定性证明。
- [Microsoft Agentic Retrieval](https://learn.microsoft.com/en-us/azure/search/agentic-retrieval-how-to-set-retrieval-reasoning-effort)：按证据缺口增加检索深度，快速/深入区别为预算与能力，不改变事实标准；不迁移框架。
- [Anthropic Context Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：提供简洁、真实的运行上下文与按需原文读取，避免特殊情形提示词堆叠。
- [PAL](https://arxiv.org/abs/2211.10435)：把可执行运算交给运行时；程序前提仍需要核对。
- [ALCE](https://aclanthology.org/2023.emnlp-main.398/)：来源存在与结论得到来源支持分别检查。
- [Agent Evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)：检查结果和调用链；模型判断用代表性真实调用校准，不以工具调用次数证明智能。

## 路由与交付边界

轻量级路线。主任务负责架构及整合；原生 gpt-5.6-sol high 执行已确定语义，独占本工作树写入。只读 Sol medium 已确认本机缺 Go、Docker daemon 未运行及现有定向测试入口。原生工具明确支持 model/effort 覆盖；此为有效配置证据，不冒充 provider-side attestation。继承主机 unrestricted/approval never，任务写授权仅本工作树；不使用外部模型执行器、不提交、不推送、不部署。

验证：变更相关 Go 包的定向测试与编译；复用已发现失败及对照题，覆盖空库、库中无答案、有答案自然问法、计算、冲突、诊断与多轮纠错。正确原文对照用于区分检索问题与模型能力。模型调用沿用现有测试账号及提供商，限定次数，不创建/修改知识库。脚本模型只能验证状态传递与执行形态，不能证明实际准确率。

停止条件：上述已确认断点修复，最小验证完成，无影响本次结果的未解决问题；不额外扩大审计、模型试跑或性能基准。

## 实施取舍

- 主链仍为问题理解 → 检索 → 重排 → 合并 → 回答，深入处理仍使用现有 AgentEngine 工具循环；未新增规划、判分或审查模型调用。
- 问题理解复用原调用，员工文本输出上限从 150 增到 250 tokens，以容纳两个独立字段；其他 Agent 保持原上限。运行时证据状态放当前用户消息，不改动每轮稳定的系统前缀。
- 重排故障沿用现有错误或可用候选降级处理；成功重排没有接受任何候选时，员工合并阶段不恢复原始弱候选。embedding 降级为关键词检索仍保留结果，同时如实标注覆盖降级。
- 文档读取复用 CustomMetadataText、原文块、父块与分页能力；保留前端原 metadata 数据契约，不把入库内部元数据投影为文档权威。
- 原文片段可以支持它实际涵盖的部分。可直接核对的简单推导仍可回答；需要完整数据或执行才能可靠得到结果时复用现有计算工具。没有工具执行证据，不声称工具核验。
- 未更换模型或增加推理预算。检索状态由代码保证；资料支持程度、诊断推导、冲突解释仍包含模型判断，不把提示原则宣称为确定性正确性保证。

## 实模对照观察及边界

源码基线是上述 206aafb4。沿用超市发与 ronsson 账号已有审查：旧运行版本的 16 次问答、206aafb4 运行版本的 8 次关键复测；旧/新版本的 16 个员工助理核心源码文件已逐字节对照。本次实施阶段另在 206aafb4 做 6 次正确原文对照调用。以下判断优先采用最新复测，未测试知识库管理。

| 对照 | 实际观察 | 可得结论 |
| --- | --- | --- |
| 超市发空库，企业制度查询 | 快速建议扩大内部检索；深入把无来源说成无权限 | 需把真实范围传到回答，不能让模式名称推导权限 |
| ronsson 有客服库，查询不相关制度 | 能承认缺依据，但仍出现无依据的制度名称、覆盖或下一步建议 | 相关片段、资料目录与完整问题支持必须分开 |
| ronsson 提供正确规则原文，快速/深入各一次 | 两种模式均出现首句与后续计算矛盾 | 不能将所有错误归因于检索；找到规则不代表正确执行 |
| 超市发空库，仅提供同一规则，快速/深入各一次 | 快速结果错，深入该次结果对 | 同样材料下表现不稳定；这两次不能证明深入或换模型必然更准 |
| ronsson 提供冲突及诊断材料，深入各一次 | 能指出部分未知，但又擅自优先某份资料或把建议升为确定结论 | 需要保留未决部分、证据角色和适用条件 |

这些是小样本问题定位，不是准确率基准。部分 ronsson 对照仍自行检索，因此不属于严格固定全部上下文的检索隔离实验。

候选代码没有部署，未通过两账号执行候选版本的真实端到端问答。现有测试账号的模型管理/调试入口受权限限制；未改变权限或绕过入口。候选提示策略的实际效果、真实延迟及是否需要换模型，仍需可运行候选环境中的同题、同模型、同预算对照决定。
